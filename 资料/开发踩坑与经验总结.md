# 门锁裸机项目开发总结：踩坑与经验

## 一、踩过的坑（按「踩坑 → 现象 → 根因 → 解法」整理）

### 1. 中文字模与源文件编码不一致 —— 屏上全是方框/问号
- **现象**：OLED 上中文字符显示成方框、问号。
- **根因**：江协科技 OLED 的 `OLED_CF16x16` 字模表是 **GB2312 索引**，而业务代码里的中文字符串若是 UTF-8 编码，索引对不上，取不到正确字模。
- **解法**：Keil 源文件统一 ANSI/GB2312，字模表和业务字符串同编码。若确需 UTF-8，则必须整体统一（含 BOM）并同步改字模表的 charset 宏。

### 2. 引脚冲突：USART1(PA9/PA10) 被薄膜键盘占用
- **现象**：想用 USART1 做调试串口，但 PA9/PA10 已经被键盘用了。
- **根因**：F103C8 引脚少（48 脚），复用严重，USART1 与键盘列扫描线撞车。
- **解法**：指纹模块改用 USART2（PA2=TX、PA3=RX）；调试输出用「开关宏」默认关闭（`FR_DEBUG_PRINT=0`），避免争抢。**这是本项目"引脚不足"的典型缩影**。

### 3. STM32F103C8 没有 TIM6/TIM7
- **现象**：编译报 `TIM7_IRQn undefined`。
- **根因**：F103C8 是**中容量(MD)**，只有 TIM1~TIM4；TIM6/TIM7 是中高容量(HD/XL)才有。之前代码是从 M4 平台移植来的，用了 TIM7。
- **解法**：把定时器全改成 **TIM4**；Keil 的 Define 里必须保留 `USE_STDPERIPH_DRIVER,STM32F10X_MD`。

### 4. 跨型号移植不是改 include 就行（F4 → F1）
- **现象**：从 F4 移植的代码编译一堆错。
- **根因**：外设库 API 差异很大。
- **解法**（关键差异清单）：
  - `RCC_AHB1PeriphClockCmd` → `RCC_APB2PeriphClockCmd`
  - `GPIO_Mode_OUT/IN` → `GPIO_Mode_Out_PP` / `GPIO_Mode_IPU`
  - F1 的 `GPIO_InitTypeDef` 没有 `GPIO_OType` / `GPIO_PuPd` 字段
  - 软件 I2C 读 ACK 时 SDA 必须切**上拉输入**，否则从机拉不低电平、应答永远失败

### 5. 新 .c 文件没加进 Keil 工程 → L6218E Undefined symbol
- **现象**：`L6218E: Undefined symbol FR_Init (referred from main.o)`。
- **根因**：新建的 usart2.c / as608.c / fingerprint.c 只放在了磁盘目录，**没通过 Keil 的"Add Existing Files"加进工程**。
- **解法**：Keil 里右键 Source Group → Add Existing Files，把新 .c 加进去。

### 6. AS608 上电握手失败（HandShake Fail）
- **现象**：复位后显示 HandShake Fail，蓝灯常亮，对调 TX/RX 也没用。
- **根因**：AS608 上电后要约 **800ms 才能稳定应答**，代码一上电就握手，太早。
- **解法**：`FR_Init()` 里先 `Delay_ms(800)` 再握手，且 `PS_HandShake` 内做 5 次重试。最终显示 `Cap:300, Valid:0` 成功。

### 7. 烧录不进去（No target connected / 下载到一半报错）
- **现象**：`No target connected` + `Flash Download failed`；之前拔插 ST-Link 能好，这次不行。
- **根因**：① 外设多（OLED+指纹+键盘）从 ST-Link 取电，拉低 3.3V；② 程序上电就抢总线（FR_Init 的延时+握手+中断），干扰 SWD 下载时序。
- **解法**：**按住复位键不放 → 点 Download → 看到开始擦写再松手**；烧录时断开外设供电、只留最小系统；Keil 里 Connect 选 under Reset。

### 8. 菜单超时功能只在 menu1 写了，二级/三级菜单不退回
- **现象**：在一级菜单能 4 秒退回时钟，但停在功能设置/指纹设置菜单就一直不退回。
- **根因**：4 秒超时逻辑只写在 `menu1()`；`menu2_config` / `menu3_fpconfig` 都是纯 `while(1)` 轮询，**根本没写超时**。
- **解法**：给每层菜单都补超时；且超时要**逐层传递**——约定 `return -1` 当"退回待机"信号往上抛，最终 main 无条件 `IdleClock_Draw()` 兜底。

### 9. 密码输入界面"下翻键"意外退出
- **现象**：改密码时按下翻键（板载键2）就退出输入。
- **根因**：`input_password()` 里 `else if (k == 2) return 0;` 把下翻键当成了"返回"，键位语义冲突（键2 在菜单里是"下移"，在输入里却被当退出）。
- **解法**：统一键位——`*`=退出、`#`=退格、键3=确认，移除下翻键的退出作用。**教训：同一个物理键在不同界面不该有互相打架的语义。**

### 10. 密码输入"跳过第一位"的 bug
- **现象**：只输一个数字提示"位数不足"后，再输入会跳过第一位。
- **根因**：提示"位数不足"重画界面后，输入下标 `idx` **没有复位为 0**。
- **解法**：重画输入界面时同步 `idx = 0`。**教训：状态变量（下标/计数）在"清屏重来"分支里必须一起复位。**

### 11. 指纹编号删除会留"空洞"
- **现象/事实**：录了 1、2、3 号，删掉 2 号后，库里实际剩 1、3，但翻看仍显示 1~2（总数变 2），编号和真实指纹错位。
- **根因**：AS608 只存模板、只支持"按 PageID 删单个"，**不提供"枚举已占用编号"的接口**，删中间必然留空洞。
- **对策**：demo 阶段接受"1~N 连续翻"，**使用习惯上"要删就删最后一个编号"**；或删前"刷指纹反查确认编号一致"再删（未做，作为增强项记录）。

### 12. 低功耗 Stop 模式——醒来的时钟恢复是最大坑
- **现象/坑**：进 Stop 后 SWD 连不上芯片，烧录失败；醒来后屏幕乱、外设异常。
- **根因**：
  1. Stop 会关 HSE + PLL，醒来回 HSI 8MHz，若不恢复，`Delay`（依赖 SysTick 72MHz）失准、外设时钟错。
  2. `SystemInit()` 恢复时钟的同时会**复位 RCC**，把之前配好的 GPIO 时钟、外设时钟全清掉，必须重建。
  3. Stop 会停调试接口时钟，导致 SWD 失效。
- **解法**：
  - 醒来第一件事 `SystemInit()` 恢复 72MHz，再重建 GPIO/OLED/USART2 等外设。
  - **烧录后门**：按住复位键再点 Download，或暂时注释掉 `EnterStopMode` 救回。
  - 唤醒源用 EXTI 外部中断，中断里只置标志、不做事，主循环统一处理。
- **关键判断**：三种低功耗模式里，门锁（电池供电 + 要显示时间 + 要保留状态）选 **Stop**——Sleep 省电不够，Standby 会清 RAM（等于复位、丢失菜单状态和指纹编号）。

### 13. Stop 模式选型：Stop 而非 Sleep/Standby
- **Sleep（睡眠）**：只停内核、外设还跑，mA 级，省电有限——不适合长期待机。
- **Stop（停机）**：时钟基本停、RAM 全保留、EXTI/RTC 唤醒，十几 μA——**门锁的最佳选择**。
- **Standby（待机）**：芯片几乎全关、RAM 全丢、醒来等于复位，最省电但体验像"重新开机"——不适合要保留状态的场景。

## 二、可复用的经验（方法论层面）

1. **先画图再写代码**：需求拆成"状态 + 事件 + 转移"，状态机图对了，代码就是照图抄。
2. **阻塞 vs 非阻塞轮询**：一句话判断——"这个状态要同时响应几件事？"大于 1 件就非阻塞轮询，别用 while(1) 死等。
3. **事件抽象层隔离硬件**：主循环只认事件码（1上/2下/3确认/10键盘/11指纹），硬件没就绪就留 stub，结构一次到位、硬件分批到货。
4. **接口与实现分离**：static 函数 = C 里的"私有"，只暴露必要的接口给上层。
5. **改前备份、改后验证**：大改动整包拷贝、副本里改、原版封存；验证不只"编译过"，要做交叉核对（如花括号配对数 = 应有数量）。
6. **报错行 ≠ 病根**：编译器报的是"发现问题的地方"，往前找真正的错位。
7. **AC5 非 C99**：变量一律函数顶部声明。
8. **计时必有回绕**：RTC 秒数相减要处理跨午夜，计数器要处理溢出。
9. **开关宏控调试**：调试输出（串口/OLED）用 `#define XXX 0/1` 开关，默认关闭，避免引脚冲突和不必要的刷屏。
10. **低频高风险操作要谨慎**：删除、改密码这类操作，宁可多一步确认，也别图快引入误操作。

## 四、如果继续做，下一步建议（受限于引脚）

1. **密码断电保存**：现在密码存 RAM，断电恢复默认。可加片内 Flash 模拟 EEPROM 或外部 EEPROM(AT24C02)。
2. **引脚复用规划**：把 PA9/PA10 从键盘解放出来，换其他 GPIO 做键盘列，即可拿回 USART1 做调试/蓝牙。
3. **指纹删除增强**：删前"刷指纹反查确认"。
4. **低功耗第二步（深度省电）**：在现有 Stop 基础上，加键盘任意键 EXTI 唤醒、指纹模块醒来的重新握手、视需要再叠 RTC 闹钟做熄屏后定时心跳。
