# DoorLock-M3 智能门锁（STM32 裸机项目）

> 一个用 STM32F103C8 单片机做的「智能门锁」演示项目。
> 本文档用大白话，尽量让**初中生也能看懂**这个项目是怎么搭起来的。

---

## 一、这是什么？能干什么？

这是一个门锁的"电子大脑"：用一块 STM32 单片机，加上屏幕、键盘、指纹模块，做出来的门锁控制核心。

它能做这些事：

| 功能 | 说明 |
|------|------|
| 🔐 密码开锁 | 在键盘上输 6 位密码，对了就"解锁成功" |
| 👆 指纹开锁 | 手指按上去，匹配到已录入的指纹就开锁 |
| 🔑 指纹管理 | 录入指纹、删除指纹、查看有几个指纹 |
| 🔒 修改密码 | 先验证旧密码，再设新密码 |
| 🕐 时钟显示 | 待机时显示日期和时间 |
| 🔋 低功耗 | 12 秒不操作就熄屏睡觉，按键再唤醒（省电） |

---

## 二、用了哪些硬件？（引脚分配表）

| 硬件 | 型号 | 接的引脚 | 干什么用 |
|------|------|---------|---------|
| 单片机 | STM32F103C8T6 | —— | 核心大脑（72MHz，中容量） |
| 屏幕 | OLED 0.96寸 SSD1306 | SCL=PB8, SDA=PB9 | 显示菜单和时间 |
| 薄膜键盘 | 3列×4行 | 列=PA8/PA9/PA10，行=PB12-15 | 输密码、输数字 |
| 板载按键 | 3 个 | 上=PB11, 下=PB1, 确认=PA6 | 菜单上下选择、确认 |
| 指纹模块 | AS608 | TX=PA2, RX=PA3, 触摸脚=PA4 | 指纹采集和比对 |
| 时钟晶振 | 32.768kHz | 接 RTC 专用脚 | 走时间（低功耗也在走） |
| 调试串口 | USART1 | PA9/PA10（**被键盘占用**） | 调试打印（当前未启用） |

> ⚠️ **重点**：PA9/PA10 本来想做调试串口，但被键盘列扫描线占用了，所以调试串口现在是关着的（代码里有个开关宏）。这是"引脚不够用"的典型例子。

## 三、整体架构：两个关键词

这个项目的核心思想就两个词：**状态机** + **事件驱动**。

### 什么是"状态机"？

把门锁想象成一个"只能处于某一种状态"的机器：

- **待机状态**：屏幕显示时间，等人操作
- **菜单状态**：显示菜单，让你选
- **开锁状态**：正在输密码 / 验指纹

程序就是一个 `while(1)` 循环，每圈判断"现在在什么状态，该干什么"。状态之间靠"事件"切换。

### 什么是"事件驱动"？

"事件"就是"发生了什么事"——按键被按了、手指摸上指纹了，这些都是事件。

程序不用一直盯着每个硬件，而是：**有事件了就处理，没事件就干等（或睡觉省电）**。

```
上电 → 初始化 → 显示时钟（待机）
        ↑                    ↓
        │              有事件发生？
        │          是↓           否↓
        │      进入对应功能    12秒后熄屏睡觉
        └────── 处理完/唤醒 ──────┘
```

## 四、事件是怎么设计的？

这是本项目**最巧的设计**，值得重点看。

### 问题：门锁要响应很多种输入

- 按板载键（上/下/确认）
- 按薄膜键盘（数字）
- 手指摸指纹模块

如果主程序里直接写"读这个脚、再读那个脚"，代码会乱成一团。

### 解法：事件抽象层（`Event_GetNum`）

不管底层是什么输入，都**翻译成一个数字（事件码）**：

| 事件码 | 含义 |
|-------|------|
| 0 | 没事发生 |
| 1 | 上键按下 |
| 2 | 下键按下 |
| 3 | 确认键按下 |
| 10 | 键盘有键按下 |
| 11 | 指纹检测到手指 |

主程序只认这些数字，不关心数字背后是哪个硬件。

代码在 `Hardware/Key.c` 的 `Event_GetNum()`：

```c
uint8_t Event_GetNum(void)
{
    uint8_t k = Key_GetNum();      // 先看板载键
    if (k) return k;                // 有就返回 1/2/3

    if (MKey_Read() != 0) return 10; // 再看键盘

    if (读指纹脚 == 高电平) return 11; // 最后看指纹

    return 0;                       // 都没事
}
```

### 好处（为什么这样设计好）

**以后加新输入方式，只需在这个函数里加几行，主程序和菜单一行都不用改。** 比如以后加"手机开锁"，就加一个"检测到手机信号返回 12"，其他地方完全不动。这就叫"**隔离会变化的东西**"。

## 五、菜单是怎么设计的？

### 菜单的层级

门锁的界面分三层，像文件夹一样一层套一层：

```
一级菜单（menu1）
 ├─ 密码解锁  → 二级：输密码
 ├─ 指纹解锁  → 二级：验指纹
 ├─ 手机解锁  → 二级（预留）
 ├─ RFID解锁  → 二级（预留）
 ├─ 功能设置  → 二级：密码修改 / 指纹设置 / RFID设置
 │              └─ 指纹设置 → 三级：查看 / 录入 / 删除
 └─ 时钟显示  → 二级：看时间
```

### 菜单怎么画出来？

每个菜单是一个 `while(1)` 循环，里面反复做：

1. **读按键**（`Key_GetNum()`）
2. **改选中项**：上键/下键改变一个叫 `flag` 的变量（表示"选中第几项"）
3. **重画屏幕**：根据 `flag` 把选中的那一行**反色显示**（黑底白字），其他行正常

反色的关键函数是 `OLED_ReverseArea`（把某一行的显示反转）。

### 菜单怎么"跳转"？

关键约定：**菜单函数通过返回值告诉上一层"我选了什么"**。

一级菜单 `menu1()` 返回一个数字（1~6），主程序 `main.c` 用 if 判断：

```c
choice = menu1();              // 用户在一级菜单选了第几项
if (choice == 1) menu2_password();   // 选了"密码解锁"
if (choice == 2) menu2_fingerprint(); // 选了"指纹解锁"
if (choice == 5) menu2_config();     // 选了"功能设置"
```

### 菜单怎么"回退"？

回退也靠返回值约定：

| 返回值 | 含义 |
|-------|------|
| `return 0` | 正常返回上一级（选了"←"） |
| `return -1` | 超时了，要一路退回待机界面 |

比如你在"指纹设置"（三级菜单）里 4 秒没动，它 `return -1`，上一层"功能设置"发现子菜单返回 -1，也 `return -1`，一路传到 `main`，`main` 就重新画待机时钟界面。

### 一个屏幕只有 4 行的处理（巧思）

OLED 屏幕是 128×64，每行 16 像素高，**一屏只能显示 4 行**。但一级菜单有 6 项，怎么办？

答案：**把整个列表"往上滚"**。当选中第 5、6 项时，不显示第 1 项，而是显示第 2~5 项或第 3~6 项，让选中的那一项始终落在屏幕可见的 4 行里。

## 六、各外设驱动是怎么设计的？

每个外设都遵循同样的套路：**初始化 → 工作 → 封装成函数 → 上层调用**。

### 1. OLED 屏幕

- **初始化**：`OLED_Init()` 发一串命令配置屏幕（`Hardware/OLED.c`，江协科技的成熟驱动）
- **工作**：屏幕分页，往显存数组里写数据，`OLED_Update()` 一次性刷到屏幕
- **封装**：`OLED_ShowString()`、`OLED_ShowNum()`、`OLED_ShowChar()` 等
- **调用**：菜单里直接 `OLED_ShowString(0, 0, "密码解锁", OLED_8X16)`

### 2. 薄膜键盘（矩阵键盘）

- **原理**：12 个键只用 7 根线（3 列 + 4 行）。扫描时"拉低一列，读 4 行"，哪个行读到低电平，就是那行列交叉的键被按了。
- **初始化**：列配成输出（初始高），行配成上拉输入
- **封装**：`MKey_Read()` 返回按下的字符（'0'~'9'、'*'、'#'）
- **调用**：密码锁里 `key = MKey_Read()` 拿到按下的数字

### 3. 板载三键

- **原理**：三个独立按键，每个接一个引脚，按下拉低
- **封装**：`Key_GetNum()` 返回 1/2/3（自带消抖）
- **调用**：菜单里读上下键和确认键

### 4. 密码锁（CodedLock）

- **流程**：输入 6 位数字（回显 `*`）→ 确认键逐位比对 → 成功/失败提示
- **默认密码**：`952700`（存在 `current_password` 数组里）
- **改密码**：`ChangePassword()` 走"验证旧密码 → 输新密码 → 确认密码 → 写入"四步
- **巧思**：输入逻辑抽成了 `input_password()` 复用函数，解锁和改密码共用同一套输入代码

### 5. 指纹模块（AS608）—— 分三层封装

指纹是**分层最清晰**的模块，值得学：

```
fingerprint.c  ← 最上层：业务（录入/验证/删除/查看）
     ↓ 调用
as608.c        ← 中间层：协议（组织命令包、解析应答包）
     ↓ 调用
usart2.c       ← 最底层：串口收发（怎么发字节、怎么收字节）
```

- **usart2.c**：管 USART2 串口，用"中断收字节 + TIM4 定时器 100ms 判帧"的方式，判断"一包数据收完了"
- **as608.c**：管 AS608 协议，比如"采图"命令是 `0x01`，"生成特征"是 `0x02`……每个命令打包发送、解析应答
- **fingerprint.c**：管业务，比如"录入"= 采图→生成特征→（防重复检查）→再采→合并→存库

**为什么要分层？** 像快递：底层管运输（串口）、中层管打包（协议）、上层管寄什么（业务）。换一个指纹模块，只改中间协议层，其他两层不动。

### 6. 低功耗（Stop 模式）

- **目的**：电池供电，省电
- **做法**：12 秒不操作 → 熄屏 + 进 Stop 停机模式（芯片大部分时钟停了）
- **唤醒**：按板载键/摸指纹，靠 EXTI 外部中断把芯片叫醒
- **醒来后**：恢复 72MHz 时钟、亮屏、回到待机界面
- **为什么选 Stop**：三种低功耗里，Sleep 省得少，Standby 会清空内存（等于重启），Stop 既省电又不丢状态，最适合门锁

### 7. RTC 时钟

- **作用**：一个内置"电子表"，靠 32.768kHz 晶振走秒
- **关键**：RTC 用独立的 LSE 晶振，即使进 Stop 低功耗也在走，所以待机时间不会停
- **时区**：RTC 存的是 UTC 时间，读出来要 +8 小时才是北京时间

## 七、有哪些"巧思"值得学？

1. **事件抽象层**：把硬件翻译成统一事件码，加新输入只改一个函数。
2. **接口与实现分离**：`static` 函数就是 C 语言里的"私有函数"，只暴露必要的接口给外面。
3. **开关宏控调试**：`FR_DEBUG_PRINT`、`FR_OLED_DISPLAY` 这些宏，改个 0/1 就能开/关调试，不用删代码。
4. **超时逐层传递**：菜单超时用 `return -1` 一路往上抛，最终回到待机。
5. **菜单窗口上移**：屏幕只有 4 行，用"滚动列表"露出第 5、6 项。
6. **状态变量要复位**：输密码"清屏重来"时，下标 `idx` 必须一起归零，否则会跳过第一位（这是踩过的坑）。
7. **复用而非复制**：密码输入逻辑抽成 `input_password()`，解锁和改密码共用。

## 八、开发时踩过的坑（注意事项）

1. **中文字模编码**：源文件要 GB2312/ANSI 编码，否则 OLED 上中文字全变方框。
2. **引脚冲突**：PA9/PA10 被键盘占了，调试串口用不了。
3. **F103C8 没有 TIM6/TIM7**：只有 TIM1~TIM4，移植代码时定时器要用 TIM4。
4. **F4 代码不能直接搬到 F1**：外设库 API 差很多（`RCC_AHB1`→`RCC_APB2` 等）。
5. **新 .c 文件要加进 Keil 工程**：否则报 `L6218E Undefined symbol`。
6. **指纹模块上电要等 800ms**：太早握手会失败。
7. **烧录进不去**：进 Stop 后 SWD 会失效，要"按住复位键再点 Download"。
8. **超时要每层都写**：只在一级菜单写超时，二级三级菜单不会自动退回。
9. **同一按键别兼职**：下翻键曾意外当"退出键"，键位语义要唯一。
10. **删指纹会留空洞**：删中间编号会让编号错位，建议删最后一个。

> 更完整的踩坑记录见 `资料/开发踩坑与经验总结.md`。

## 九、怎么编译烧录？

1. **打开工程**：Keil MDK 打开 `Project.uvprojx`
2. **确认宏定义**：`Options → C/C++ → Define` 里要有 `USE_STDPERIPH_DRIVER,STM32F10X_MD`
3. **新文件要加进工程**：如果新增了 .c 文件，右键 Source Group → Add Existing Files
4. **编译**：F7 编译，看有没有报错
5. **烧录**：ST-Link 连接，**按住板子复位键 → 点 Download(F8) → 开始擦写后松手**（这样能避开低功耗模式下 SWD 失效的问题）
